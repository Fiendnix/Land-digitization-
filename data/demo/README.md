# Fictional demonstration dataset

All people, parcel identifiers, locations, reference rows, and geometries in
this folder are synthetic and illustrative. They are not government records,
official reference data, legal evidence, or authoritative boundaries. The
GeoJSON uses longitude/latitude coordinates in a fictional area and requires
no external map service as a data file. The app map backdrop
uses Esri World Imagery and requires internet access; the sample shapes still
work without it.

- `records.csv` contains ten deterministic demo records with intentionally
  varied review conditions.
- `reference_records.csv` is a separate fictional comparison dataset. The
  owner for `DEMO-PARCEL-007` intentionally differs to demonstrate a mismatch.
- `parcel_geometries.geojson` has valid polygons, two overlapping pairs, and
  one self-intersecting polygon.
- `test_documents/` contains three clearly fictional OCR PDFs (a complete record, a missing-owner/duplicate-survey example, and an invalid-area worn-scan example). These are synthetic, visibly aged and skewed, marked not for legal use, and have no official emblems, seals, or signatures. Regenerate their seeded layouts and scan textures with `uv run python scripts/generate_test_documents.py`.
- `sample-land-record.png` is generated by `uv run python scripts/seed_demo.py`
  as a synthetic scanned-style document for `DEMO-PARCEL-001`. Upload it from
  the Digitize Record page to demonstrate OCR and human correction.

To supply another sample scan, print a copy of `records.csv`'s first data row
with the dataset disclaimer above it, scan it as PNG/JPG or scanned PDF, and
upload that scan. Do not replace the disclaimer or present it as a real record.

## Seed and reset

Seed the isolated demo database and start the app against it:

```sh
uv run python scripts/seed_demo.py
LAND_RECORDS_DB=data/demo_land_records.sqlite3 LAND_RECORDS_DEMO=1 uv run streamlit run app.py
```

The seed is idempotent: rerunning it against a fully seeded database makes no
record, validation, alert, or audit duplicates. It refuses a partially seeded
database rather than guessing which local information is safe to overwrite.

To reset, run:

```sh
uv run python scripts/seed_demo.py --reset
```

The script displays a warning naming `data/demo_land_records.sqlite3` and asks
for explicit confirmation before removing that isolated database and its
SQLite WAL/SHM sidecars. Use `--yes` only when intentionally automating this
destructive reset. The application's ordinary `data/land_records.sqlite3`
database is never reset by this command.
