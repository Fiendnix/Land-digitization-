# Integration contract

This document defines the shared data and persistence interfaces for the
hackathon modules. Keep module integrations on these names and types; coordinate
before changing the schema or public function signatures.

## Shared models

Import the dataclasses from `modules.models` (or from `modules`):

- `LandRecord`: `record_id: str` (UUID4 string, generated by the app),
  `parcel_id: str | None`, `survey_number: str | None`,
  `owner_name: str | None`, `village: str | None`, `taluka: str | None`,
  `district: str | None`, `state: str | None`, `area: float | None`,
  `area_unit: str | None`, `land_use: str | None`,
  `document_path: str | None`, `created_at: str`, and `updated_at: str`.
  The record ID and UTC timestamps are generated by default. All other
  attributes default to `None` when unknown. Parcel IDs and survey numbers are
  not unique.
- `ValidationResult`: required `record_id: str`, `validation_type: str`, and
  `status: Literal["passed", "failed", "needs_review"]`; plus
  `validation_id: str` (UUID4 by default), `details: dict[str, object] | None`,
  and `created_at: str`.
- `Alert`: required `record_id: str`, `severity: Literal["low", "medium",
  "high", "critical"]`, and `message: str`; plus `alert_id: str` (UUID4 by
  default), `is_resolved: bool` (defaults to `False`), and `created_at: str`.
- `AuditEvent`: required `event_type: str`; plus `record_id: str | None`,
  `actor_id: str | None`, `event_id: str` (UUID4 by default),
  `details: dict[str, object] | None`, and `created_at: str`.

All timestamps use ISO 8601 strings in UTC with an explicit `+00:00` offset.
The current dataclasses generate timestamps when instantiated. JSON-like
`details` values map to the corresponding SQLite `details_json` text column
using JSON serialization when persisted by a future module.

## Database API

Import from `modules.database` or `modules`:

```python
initialize_database(db_path: str | Path = DEFAULT_DATABASE_PATH) -> None
create_record(
    record: LandRecord,
    db_path: str | Path = DEFAULT_DATABASE_PATH,
) -> LandRecord
get_record(
    record_id: str,
    db_path: str | Path = DEFAULT_DATABASE_PATH,
) -> LandRecord | None
list_records(db_path: str | Path = DEFAULT_DATABASE_PATH) -> list[LandRecord]
```

Call `initialize_database()` before using the other functions. The default
database is `data/land_records.sqlite3`, relative to the process working
directory. A caller can supply a different path, including a temporary path
for tests. `create_record()` inserts the caller's app-generated ID and returns
the same record; a duplicate record ID raises SQLite's integrity error.
`get_record()` returns `None` when the ID does not exist. `list_records()`
returns records ordered by `created_at`, then `record_id`.

The API uses parameterized SQL, enables SQLite foreign-key enforcement for each
connection, and commits each operation in a transaction. It does not generate
IDs in SQLite. Unknown optional values are stored as SQL `NULL`.

## SQLite schema

`initialize_database()` creates these tables:

| Table | Columns and SQLite types | Relationships / constraints |
|---|---|---|
| `land_records` | `record_id TEXT`, `parcel_id TEXT`, `survey_number TEXT`, `owner_name TEXT`, `village TEXT`, `taluka TEXT`, `district TEXT`, `state TEXT`, `area REAL`, `area_unit TEXT`, `land_use TEXT`, `document_path TEXT`, `created_at TEXT`, `updated_at TEXT` | `record_id` is the primary key; timestamps are required. Parcel and survey values are not unique. |
| `validation_results` | `validation_id TEXT`, `record_id TEXT`, `validation_type TEXT`, `status TEXT`, `details_json TEXT`, `created_at TEXT` | `validation_id` primary key; required record FK; status is `passed`, `failed`, or `needs_review`; deleting a record cascades. |
| `alerts` | `alert_id TEXT`, `record_id TEXT`, `severity TEXT`, `message TEXT`, `is_resolved INTEGER`, `created_at TEXT` | `alert_id` primary key; required record FK; severity is `low`, `medium`, `high`, or `critical`; resolved is `0` or `1`; deleting a record cascades. |
| `audit_events` | `event_id TEXT`, `record_id TEXT`, `event_type TEXT`, `actor_id TEXT`, `details_json TEXT`, `created_at TEXT` | `event_id` primary key; nullable record FK; deleting a record sets it to `NULL`. |

The initial database API only implements create, get, and list operations for
`LandRecord`. The other dataclasses and tables define the shared persistence
contract; CRUD or validation behavior for them is not part of this foundation.

## Module boundaries for integration

- Core/database owns `modules.models`, `modules.database`, and the SQLite
  schema. Other modules pass `LandRecord` instances and use `record_id` for
  references; they must not treat parcel or survey identifiers as primary
  keys.
- Document-processing code can supply a local `document_path`; extracted
  values should populate the optional `LandRecord` attributes. OCR behavior
  and document storage are outside this contract.
- Validation code can represent outcomes with `ValidationResult` and
  associated user-facing issues with `Alert`. This foundation does not define
  validation rules or trust scores.
- UI code can call the database API and consume the shared dataclasses. This
  contract does not define dashboard or GIS behavior.

## Environment and tests

Use `uv` for project and development dependencies. From the repository root:

```powershell
uv sync --group dev
uv run --group dev python -m pytest
```

The database tests create SQLite files under pytest's temporary directory;
they do not use the default application database.
